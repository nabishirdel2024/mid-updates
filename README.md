# MID Updates — نسخه‌های انتشار ژورنال معاملاتی

این مخزن مانیفست شماره نسخه‌های انتشار برنامه‌های «ژورنال معاملاتی MID» و «پنل ادمین» آن را نگه می‌دارد. کد خودِ برنامه‌ها در این مخزن قرار ندارد.

## ساختار مخزن

```text
mid-updates/
├── version.json              # مانیفست نسخه‌های انتشار
├── README.md                 # همین سند
├── CHANGELOG.md              # تاریخچه به‌روزرسانی مانیفست
├── schemas/
│   └── version.schema.json   # قرارداد رسمی ساختار مانیفست
└── .github/
    └── workflows/
        └── validate.yml      # اعتبارسنجی خودکار مانیفست
```

## قرارداد فایل version.json

- یک شیء JSON با دو کلید `journal` و `admin` است؛ هر دو مقدار رشته‌ای و غیرخالی دارند.
- `journal` شماره نسخه انتشار ژورنال و `admin` شماره نسخه انتشار پنل ادمین است.
- دو مقدار لازم نیست یکی باشند؛ در زمان نگارش این سند هر دو `4.1.2-r11` هستند.
- تعریف دقیق و رسمی این قرارداد در [`schemas/version.schema.json`](schemas/version.schema.json) آمده است.

## فرآیند پیشنهادی نگهداری و انتشار نسخه

1. مقدار کلید مربوطه در `version.json` به‌روزرسانی می‌شود.
2. یک ورودی برای نسخه جدید در `CHANGELOG.md` ثبت می‌شود.
3. تغییرات به شاخه `main` کامیت می‌شوند.
4. در هر push و pull request، workflow اعتبارسنجی (`.github/workflows/validate.yml`) بررسی می‌کند که `version.json` از نظر ساختار JSON معتبر و منطبق با اسکیما باشد.

**نکته:** شاخه `main` محافظت‌شده نیست؛ بنابراین workflow اعتبارسنجی نتیجه نامعتبربودن را فقط گزارش می‌کند و به‌تنهایی مانع کامیت مستقیمِ نامعتبر نمی‌شود.

**نکته:** این فرآیند، فرآیند پیشنهادی برای نگهداری این مخزن است، نه توصیف تأییدشدهٔ فرآیند فعلی ناشرِ نسخه‌ها.
